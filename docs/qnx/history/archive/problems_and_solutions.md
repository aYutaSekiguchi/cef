## Phase 2: Disabling Dependencies via GN Args

### Toolchain Path Issue
- **Error**: `//third_party/llvm-build/.../clang++: not found`
- **Cause**: `clang_base_path`'s `//` is expanded as file system root
- **Fix**: Use `rebase_path()` in `build/toolchain/qnx/BUILD.gn`

### sysroot Issue
- **Error**: Debian Bullseye sysroot is used
- **Fix**: Added QNX branch in `build/config/sysroot.gni` (`sysroot = getenv("QNX_TARGET")`)

### Toolchain Name Mismatch
- **Error**: `Unresolved dependencies. //... needs //build/toolchain/qnx:clang_x64()`
- **Cause**: `_default_toolchain = "//build/toolchain/qnx:clang_$target_cpu"` but defined as `qnx_clang_toolchain("x64")` in BUILD.gn
- **Fix**: Changed to `qnx_clang_toolchain("clang_x64")`

## 2026-05-11: New/Resolved Issues

### ✅ Resolved: third_party/ced - uint32/int32 Undefined
**Cause**: QNX `sys/platform.h` defines `_INT32`/`_UINT32`. The guard names `_INT32`/`_UINT32` in `basictypes.h` conflict and skip the typedef.
**Fix**: Changed guard names to `_CED_INT32`/`_CED_UINT32`.
**File**: `third_party/ced/src/util/basictypes.h`

### ✅ Resolved: google_benchmark → libpfm4 (sys/syscall.h not found)
**Cause**: `if (is_linux)` is true on QNX → `HAVE_LIBPFM=1` + libpfm4 dependency.
**Fix**: Changed to `if (is_linux && !is_qnx)`.
**File**: `third_party/google_benchmark/BUILD.gn`

### ✅ Resolved: libatomic.so Link Failure
**Cause**: `qcc` linker cannot interpret `--target=x86_64-unknown-linux-gnu`. Default compiler config adds Linux target triple to ldflags.
**Fix**: Changed linker from `qcc` to `clang++`. Added `--target` and definitions to `extra_ldflags`. Added `is_qnx` branch in `build/config/compiler/BUILD.gn` to skip Linux target triple.
**Files**: `build/toolchain/qnx/BUILD.gn`, `build/config/compiler/BUILD.gn`

### ✅ Resolved: fontconfig Bindgen (sys/stat.h Type Errors)
**Cause**: bindgen's `${cflags}` has `--target=x86_64-unknown-linux-gnu` hardcoded, incompatible with QNX sysroot. Missing QNX defines make sys/stat.h types undefined.
**Fix**: Added `is_qnx` branch for each CPU (x64/x86/arm/arm64) in `build/config/compiler/BUILD.gn` to set QNX target triple and defines.
**File**: `build/config/compiler/BUILD.gn`

### ❌ Unresolved: perfetto VSOCK (AF_VSOCK)
**Cause**: `<linux/vm_sockets.h>` not found on QNX. `AF_VSOCK` is Linux kernel-specific.
**Proposed Fix**: Guard VSOCK code path with `#if !defined(__QNX__)`.
**File**: `third_party/perfetto/src/base/unix_socket.cc`

## 2026-05-11: New/Resolved Issues (Continued)

### ✅ Resolved: std::ranges::contains Missing (1000+ Locations)
**Cause**: QNX libc++ 18.1 does not implement C++23 `std::ranges::contains`.
**Fix**: Implemented polyfill in `build/config/qnx/qnx_std_polyfill.h`, injected into all C++ translation units via QNX toolchain's `-include`. Guarded with `__cpp_lib_ranges_contains`.

### ✅ Resolved: proc_maps_qnx.cc — num_segments Missing
**Cause**: `_debug_process_info::num_segments` does not exist on QNX.
**Fix**: Pass NULL buffer to `DCMD_PROC_MAPINFO` to get segment count. Added required headers (`<inttypes.h>`, `<stdio.h>`, `<string>`, `<sys/mman.h>`).
**File**: `base/debug/proc_maps_qnx.cc`

### ✅ Resolved: file_posix.cc — futimes Not Available
**Cause**: QNX sysroot has no `futimes` but has `futimens`.
**Fix**: Changed to `#if defined(__USE_XOPEN2K8) || BUILDFLAG(IS_QNX)` to enter futimens path.
**File**: `base/files/file_posix.cc`

### ❌ Unresolved: base_unittests Remaining Errors (10+)

## 2026-05-12: QCC Linker Path Resumption and libatomic.so Passing

### ✅ Resolved: `use_lld=false` in Global Breaks Host Rust Tools
**Error**: Unresolved symbols like `errno@GLIBC_PRIVATE` during `clang_x64_for_rust_host_build_tools` linking.
**Cause**: Setting `use_lld=false` in args.gn changes not just the QNX target but also the host toolchain to `/usr/bin/ld` behavior.
**Fix**: Abandoned global `use_lld=false`, switched to adjusting only the QNX target side for QCC.

### ✅ Resolved: `--target=x86_64-unknown-nto` Leaking into QCC Link
**Error**: `cc: unknown option: --target=x86_64-unknown-nto`
**Cause**: QNX CPU branch in `build/config/compiler/BUILD.gn` was adding compile-only `--target=...` to ldflags as well.
**Fix**:
- Removed `ldflags += [ "--target=..." ]` for QNX in `build/config/compiler/BUILD.gn`
- Set `extra_ldflags = "-Vgcc_ntox86_64_cxx"` for QCC in `build/toolchain/qnx/BUILD.gn`

### ✅ Resolved: `-fuse-ld=lld` Leaking into QCC Link
**Error**: `cc: unknown option: -fuse-ld=lld`
**Cause**: Standard Chromium LLD flags were entering QNX link as well.
**Fix**:
- Set `use_lld = false` when `current_os == "qnx"` in `build/config/compiler/compiler.gni`
- Changed `-fuse-ld=lld` addition condition to include `current_os != "qnx"` in `build/config/compiler/BUILD.gn`

### ✅ Resolved: `-no-canonical-prefixes` Leaking into QCC Link
**Error**: `cc: unknown option: -no-canonical-prefixes`
**Cause**: Deterministic flag assuming clang driver was also entering QCC.
**Fix**: Excluded QNX from the `compiler_deterministic` config in `build/config/compiler/BUILD.gn`.

### ✅ Resolved: `--sysroot=...` Leaking into QCC Link
**Error**: `cc: unknown option: --sysroot=../../../../qnx800/target/qnx`
**Cause**: `runtime_library` config in `build/config/posix/BUILD.gn` was adding linker sysroot flags for all of POSIX.
**Fix**: Stopped `ldflags += sysroot_flags` only for QNX; kept compile-side sysroot.

### ✅ Resolved: `-ldl -lpthread -lrt` Unresolvable by QNX
**Errors**:
- `ld: cannot find -ldl`
- `ld: cannot find -lpthread`
- `ld: cannot find -lrt`
**Cause**: QNX was entering Linux branch in `build/config/BUILD.gn`'s `default_libs`, injecting Linux default libraries.
**Fix**: Added `is_qnx` branch before Linux in `build/config/BUILD.gn`'s `default_libs`, setting `libs = []`.

### ✅ Milestone: `libatomic.so` Passes Through QCC Path
**Confirmation**:
- `out/qnx_x64/libatomic.so` generated
- `out/qnx_x64/libatomic.so.TOC` generated
- `ninja -C out/qnx_x64 libatomic.so` succeeded

### ✅ Resolved: Rust Target Triple Becoming Linux on QNX
**Error/Symptom**:
- QNX target build using `x86_64-unknown-linux-gnu` stdlib
- Linux-only Rust std unresolved errors
**Cause**: `is_linux || is_chromeos` branch in `build/config/rust.gni` was evaluated before `is_qnx`, causing QNX to pick Linux triple.
**Fix**: Moved `is_qnx` branch before `is_linux` in `build/config/rust.gni`, ensuring `rust_abi_target = x86_64-pc-nto-qnx800` is selected.

### ✅ Resolved: `qnx_std_polyfill.h` `<version>` Error Was Environment-Caused
**Error**:
- `build/config/qnx/qnx_std_polyfill.h:19:10: fatal error: 'version' file not found`
**Cause**:
- `gn gen` was run without `QNX_HOST` / `QNX_TARGET`, embedding:
  - `--sysroot=`
  - `-I/usr/include/c++/v1`
  - `/usr/bin/qcc`
- Actual QNX sysroot has `<QNX_SDP_ROOT>/target/qnx/usr/include/c++/v1/version`.
**Fix**:
- Re-ran `gn gen out/qnx_x64` in the correct environment.
- No code fix needed.

### ✅ Resolved: Rust rlib Must Be Followed by System libs on QNX
**Error**:
- `getsockname`, `recvfrom`, `getpeername`, `connect`, `sendto`, `bind`, etc. unresolved from `libstd_std.rlib`
**Cause**:
- `{{libs}}` was placed before `{{rlibs}}` in `solink` / `link` in `build/toolchain/gcc_toolchain.gni`.
- On QNX `qcc` / `ld`, this order prevented Rust rlib from resolving `-lsocket`, etc.
**Fix**:
- `build/toolchain/gcc_toolchain.gni`
  - `tool("solink")`
  - `tool("link")`
- For QNX only, moved `{{libs}}` after `{{rlibs}}`.
- Manual re-link experiment confirmed this order change succeeded.
- `ninja -C out/qnx_x64 libthird_party_fontconfig.so` succeeded.

### ✅ Resolved: QNX epoll/inotify Integration
**Background**:
- `message_pump_epoll.cc` compiled on QNX, causing `epoll_create1`, `epoll_ctl`, `epoll_wait` unresolved
- `file_path_watcher_inotify.cc` compiled on QNX, causing `inotify_init`, `inotify_add_watch` unresolved
**Investigation**:

**Fix**:

- Created `third_party/epoll/BUILD.gn` (compiles `epoll.c`, `epoll-mgr.c`)
- Added `fsnotify` to QNX `default_libs` in `build/config/BUILD.gn`
- `base/BUILD.gn`:
  - `use_epoll = is_linux || is_chromeos || is_android || is_qnx`
  - Added `|| is_qnx` to `file_path_watcher_inotify.cc` guard
  - Added `deps += [ "//third_party/epoll:epoll" ]` for QNX
- `third_party/epoll/src/epoll-mgr.c`: Changed `__sigevent32` assignment to `memcpy`
