### clang_lib() template — the builtins resolver
```python
# build/config/clang/BUILD.gn (lines 128-248)
template("clang_lib") {
  # ...
  if (is_qnx) {
    if (current_cpu == "x64") {
      _dir = "x86_64-unknown-nto"
    } else if (current_cpu == "arm64") {
      _dir = "aarch64-unknown-nto"
    }
  }
  # ...
  _clang_lib_dir = "$clang_base_path/lib/clang/$clang_version/lib"
  _lib_file = "${_prefix}clang_rt.${_libname}${_suffix}.${_ext}"

}
```

## Open Questions

1. **Who builds the pre-packaged nto builtins?** The `x86_64-unknown-nto/libclang_rt.builtins.a` exists in the local tree but is not generated by any Chromium build step. It likely comes from a separate QNX-specific clang packaging job not reflected in `package.py`.

2. **Is the existing artifact sufficient?** For Option B, verify the existing artifact covers all needed builtins (atomic operations, stack tracking, integer ops) for QNX NTO.

3. **Can clang_lib() be overridden per-toolchain?** The template currently resolves paths from global `clang_base_path`. A per-toolchain override would require modifying the QNX toolchain invocation to set a different base path, or adding a conditional in `clang_lib()`.
