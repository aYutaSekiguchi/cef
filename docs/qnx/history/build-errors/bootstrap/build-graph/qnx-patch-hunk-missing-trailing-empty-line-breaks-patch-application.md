# QNX patch hunk missing trailing empty line breaks patch application

- Date: 2026-06-15
- Signature: `corrupt patch at line \d+`, `@@ -\d+,\d+ \+\d+,\d+ @@` hunk body shorter than header, `git apply` aborts on the last hunk
- Stage: bootstrap
- Category: build-graph
- Scope: `cef/patch/patches/qnx/chromium/mojo_webui_version_ts_qnx` (single hunk, one-line `is_qnx` addition to `ui/webui/resources/mojo/BUILD.gn`)

## Symptoms

- `cef_create_projects_qnx.sh` aborts with: `Apply mojo_webui_version_ts_qnx.patch in <src> ... failed to apply: error: corrupt patch at line 13`.
- The patch is the only failure in a long sequence; `git apply` reports a parser error at a line that is one past the visible end of the file.
- Inspecting the patch file shows the hunk header is `@@ -99,7 +99,7 @@ if (is_chromeos) {` (declaring 7 old + 7 new lines) but the hunk body has 6 old + 6 new lines. The trailing empty line that should follow the last ` }` context line is missing.
- The same patch, when regenerated by `git diff --no-prefix --relative --full-index` from a tree where the change has been applied, produces a correctly terminated 13-line patch that `patch -p0 --batch` accepts.

## Root cause

- A hand-edited or tooling-truncated unified diff was committed with a malformed hunk. The hunk header's line count is not equal to `context + removed` (old side) or `context + added` (new side), and the file lacks the trailing empty line that `git apply` and `patch` both require as a hunk terminator.
- `git diff` with default `-U3` produced a hunk in this case where the trailing empty line of the change's enclosing block was outside the 3-line post-context window, so the hand-rolled commit body mirrored that undercount.
- The bootstrap's per-patch applier catches this as a hard error and aborts. There is no fuzzy fallback for this kind of structural problem (only for ordinary context mismatch, which is what the 3 known rebase-collision patches need).

## Fix pattern

- Treat `patch -p0 --batch --dry-run` against a clean source tree as the validation step for any new or edited QNX patch before committing it.
- When a patch fails to apply with "corrupt patch at line N" or "hunk body shorter than header", regenerate the patch from a working tree where the change is present, using either:
  - `python3 cef/tools/patch_updater.py --resave --patch=<patch-name>` (preferred, also fixes trailing-newline and Windows-line-ending issues), or
  - `git diff --no-prefix --relative --full-index <path>` from the correct patch root, then verify the resulting hunk line count matches the header.
- After regeneration, always confirm `patch -p0 --batch` accepts the file (exit code 0, no `failed` lines in output) on a clean tree, then commit.
- Do **not** edit patch files by hand to add or remove context lines — the regenerate-from-tree path is faster and produces a verifiably correct file.
