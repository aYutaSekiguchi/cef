# QNX Mesa LoaderPrivate warning isolation (2026-07-20)

## Symptom

System Mesa EGL prints the following warning repeatedly while running
`cefsimple`:

```text
libEGL warning: qs_destroy_loader_image_state(): LoaderPrivate argument is not NULL, can't handle this!
```

## Minimal reproduction

The standalone `qnx_dmabuf_export_only_probe` reproduces one warning without
Chromium, CEF, Screen windows, GL contexts, or DMAbuf IPC. Cleanup markers were
flushed around `eglDestroyImageKHR` and `eglTerminate`.

| Operations | Warning |
|---|---:|
| EGL initialize then terminate; no image | 0 |
| `eglCreateDRMImageMESA`, no export, then destroy | 1 |
| Create/export, then destroy | 1 |
| Create/export, skip destroy, then terminate | 1 |
| Create/export, skip both destroy and terminate | 0 |

This proves that `eglCreateDRMImageMESA` is sufficient to create the state that
causes the warning. Exporting or closing the exported fd is not required. If
the application destroys the image, the warning is emitted during
`eglDestroyImageKHR`; otherwise Mesa emits it while cleaning the image during
`eglTerminate`.

The guest implementation is `/usr/lib/EGL-mesa.so` (522560 bytes, image build
timestamp 2026-01-16). The warning string and adjacent `qs_*` diagnostics are
embedded in that DSO; `qs_destroy_loader_image_state` is not a dynamic symbol.
Its implementation/source is therefore not available for an application-side
patch in this checkout.

## Interpretation

The warning is generated by the QNX Mesa EGL provider's image cleanup code. It
does not demonstrate that Chromium omitted `eglDestroyImageKHR`; the same
warning occurs when the minimal probe calls that API correctly. Skipping image
destruction only moves the warning to `eglTerminate`, and skipping both merely
hides it by leaking the display/image until process exit.

The repeated `cefsimple` warning count is consistent with Mesa cleaning
multiple internal loader-image states. The serial log does not attach a PID or
image handle to each Mesa warning, so an exact mapping from each line to a
Chromium resource is not proven.

## Safe log mitigation

Mesa honors `EGL_LOG_LEVEL=fatal`. With that environment variable:

- normal `eglDestroyImageKHR` and `eglTerminate` were retained;
- the export-only probe still completed successfully;
- warning count changed from 1 to 0;
- `cefsimple` loaded `about:blank` (`OnLoadEnd`, status 0 and `loading=0`);
- `cefsimple` warning count was 0.

Use:

```sh
./tools/qnx_run.sh --virgl --preload-system-egl \
  --env EGL_LOG_LEVEL=fatal -- \
  ./cefsimple --ozone-platform=qnx --use-gl=egl --use-native --no-sandbox
```

This suppresses every Mesa EGL warning, not only this message. It is suitable
for keeping routine runtime logs readable, but diagnostic runs should omit it.
