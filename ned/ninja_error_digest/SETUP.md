# `ned` setup

How to install and maintain the local Python environment that provides the
`ned` command used to compress Ninja build logs for AI consumption.

## TL;DR

```bash
# From the repository root
uv venv .venv
uv pip install -e ned/
.venv/bin/ned --version   # should print: ninja-error-digest 0.1.0
```

That's it. The `ned` entry point is then available as `.venv/bin/ned`.

## What is `.venv/`?

`ned` is a Python package defined in `ned/pyproject.toml`
and source-laid out under `ned/ninja_error_digest/`. The local `.venv/`
directory is a project-scoped virtual environment that contains:

- a private Python interpreter
- the `ned` package (installed in editable mode, so edits under
  `ned/ninja_error_digest/` take effect immediately)
- the `ned` console-script entry point at `.venv/bin/ned`

`.venv/` is **not** committed. The QNX / CEF `.gitignore` is regenerated by CEF
tools, so a stale exclusion there is not a reason to track it. Each agent or
developer must create `.venv/` themselves.

## Prerequisites

- Python 3.8 or newer available on `$PATH`
- [`uv`](https://docs.astral.sh/uv/) (preferred) or `python -m venv` + `pip`

`uv` is the recommended tool — it is faster, deterministic, and handles
interpreter resolution. If `uv` is not available, the fallback is:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ned/
```

## Standard setup

```bash
# 1. Create the venv (one-time, ~1 second)
uv venv .venv

# 2. Install ned in editable mode (one-time per .venv)
uv pip install -e ned/

# 3. Optional: install pytest so you can run the test suite
uv pip install pytest
```

Verify the install:

```bash
.venv/bin/ned --help
.venv/bin/ned --version
.venv/bin/pytest ned/tests/ -v   # if pytest was installed
```

## Refreshing a stale venv

If the venv already exists but the package or its dependencies have changed
(for example, after a `git pull` that touches `pyproject.toml` or any module
under `ned/ninja_error_digest/`), refresh it in place:

```bash
uv pip install -e ned/ --reinstall
```

You only need to recreate the venv from scratch if Python itself changed or
the venv is corrupted.

## Removing a stale venv

It is always safe to delete `.venv/` and recreate it. There are no caches or
artifacts that survive a venv that you would lose:

```bash
rm -rf .venv
uv venv .venv
uv pip install -e ned/
```

The full round trip is a few seconds.

## Troubleshooting

**`uv: command not found`** — install `uv` first:

```bash
# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**`ned: command not found`** after install — make sure you invoke
`.venv/bin/ned` explicitly, or activate the venv:

```bash
source .venv/bin/activate
ned --version
```

**Permission denied on `.venv/bin/ned`** — never `chmod +x` system files; the
script is already executable. Re-run `uv pip install -e ned/` from the
repository root.

**Tests fail with `ModuleNotFoundError: ned`** — you are not running from the
project-local venv. Use `.venv/bin/pytest`, not a system `pytest`.
